# wm_social_robot

Simulation and dataset tooling for an action-conditioned world model for social
robot navigation, built on **Arena-Rosnav (branch `humble`)**: ROS 2 Humble +
Nav2 + **Gazebo Harmonic** (HuNavSim pedestrians) or **Isaac Sim 4.2** (NVIDIA
animated characters), running in a Docker container with the NVIDIA GPUs. The
sources stay on the host and are bind-mounted into the container.

## Quick reference

```bash
./run.sh shell                                   # on the host: shell in the container
arena_sim world:=hospital peds:=8                # Gazebo, headless
arena_sim world:=hospital peds:=8 gui:=true      # Gazebo window + RViz (GPU via VirtualGL)
arena_sim sim:=isaac world:=map_empty peds:=6 gui:=true  # Isaac Sim window + RViz
arena_sim sim:=isaac world:=isaac_hospital peds:=8 gui:=true  # NVIDIA's Isaac hospital scene (Arena's Video_hospital.gif)
arena_stop                                       # stop everything that is left
python3 ~/wm_social_robot/tools/sim_check.py     # rates of LiDAR/odom/cmd_vel/pedestrians, real-time factor
```

| `docker/nvidia-extra/` | generated by `run.sh build`: NVIDIA OptiX/NGX libraries matching the host driver |
| `docker/install_arena.sh` | superseded (Arena's upstream installer, compiles ROS from source) |

| `patches/` | local fixes to Arena repos, applied with `tools/arena_patches.sh` |

The workspace directory must be called `arena4_ws`: Arena's
`gazebo_entity_spawn.py` looks for that name, and the code expects the Arena
repository at `$ARENA_WS_DIR/src/arena/arena-rosnav`.

## Docker architecture

```
host (Debian 13, no sudo)                       container wm-<user>  (image wm-social-robot:<user>, ~21 GB)
~/wm_social_robot  ── bind mount ─────────────▶ /home/<user>/wm_social_robot      (same path, rw)
                                                  arena4_ws/src      sources, edited on the host
Docker volume ws_build   ─────────────────────▶   arena4_ws/build    colcon outputs on local disk,
Docker volume ws_install ─────────────────────▶   arena4_ws/install  not on the NFS home
Docker volume ws_log     ─────────────────────▶   arena4_ws/log
Docker volume home       ─────────────────────▶ /home/<user>          ~/.ros logs, Isaac shader caches
/tmp/.X11-unix, X cookie ─────────────────────▶ GUI windows
2x RTX A4000 (compose device reservation)
                                                /opt/isaac-sim        Isaac Sim 4.2 (in the image)
```

* The container runs as the host user (same name, UID and GID, built in with
  build args), so files created in `arena4_ws/src` belong to you on the host.
  `HOME=/home/<user>`. `sudo` works without password inside, for experiments only:
  anything that must persist goes into the Dockerfile.
* Image dependencies are reproducible: `rosdep install` runs **at image build
  time** over the `package.xml` files of `arena4_ws/src` (nothing else of the
  workspace enters the build context). Rerun `./run.sh build` whenever
  dependencies in a `package.xml` change.
* The ROS environment is loaded automatically in every shell (`/etc/bash.bashrc`
  sources `docker/arena_env.bash` from the bind mount).
* `DISPLAY` is passed per command by `run.sh`; start `./run.sh shell` from a
  terminal of the ThinLinc desktop to get windows.

## First-time setup (on the host)

```bash
cd ~/wm_social_robot
./run.sh setup        # build image, import the repos (exact commits) + apply patches, rebuild with their deps
./run.sh ws-build     # colcon build of arena4_ws (~5 min on this machine)
./run.sh gpu-test     # optional: lists both RTX A4000 under Vulkan and OpenGL (VirtualGL)
```

On this machine all three steps have already been done. The first image build
downloads ~25 GB (Isaac Sim image from nvcr.io included); `INSTALL_ISAAC=0
./run.sh build` leaves Isaac Sim out.

`./run.sh import` imports `arena4_ws/workspace.lock.repos` (exact tested
commits) and applies `patches/`. Arena's own `.repos` pins are used only if
the lock file is missing.

## Running simulations: `arena_sim` / `wm_bringup`

`arena_sim [args]` (inside the container) = `ros2 launch wm_bringup sim.launch.py
[args]`, run through VirtualGL when a window is requested and with Isaac Sim's
environment when `sim:=isaac`. All options:
`ros2 launch wm_bringup sim.launch.py --show-args`.

| Argument | Default | Meaning |
|---|---|---|
| `sim` | `gazebo` | `gazebo` \| `isaac` \| `dummy` |
| `world` | `map_empty` | `factory`, `generated`, `hospital`, `house17`, `ignc`, `map_empty`, `small_warehouse`; Isaac only: `isaac_hospital` |
| `peds` | `1-3` | pedestrians per episode: `N` or `MIN-MAX` |
| `ped_model` | Arena default | Gazebo: `gazebo_actor`, `actor1`, `actor2` (Isaac picks among 22 NVIDIA characters itself) |
| `ped_rate` | `50` | Gazebo: pedestrian update rate [Hz sim time] (upstream 1000) |
| `obstacles` | `3-5` (`0` in `isaac_hospital`) | static obstacles per episode: `N` or `MIN-MAX` |
| `obstacle_models` | Arena default / USD models | comma-separated static obstacle models |
| `gui` | `false` | simulator window (Gazebo GUI / Isaac Sim) + RViz |
| `rviz` | `false` | RViz only |
| `render` | `ogre` | Gazebo renderer: `ogre` (Arena default) \| `ogre2` (PBR; headless on the GPU through EGL) |
| `isaac_renderer` | `RayTracedLighting` | Isaac Sim: `RayTracedLighting` (real-time RTX) \| `PathTracing` |
| `isaac_hz` | `20` | Isaac Sim: render/sensor frames per simulated second, physics stays at 60 Hz (`60` = upstream, half the speed) |
| `camera` | `follow` | Isaac Sim window: `follow` (chase camera behind the robot) \| `free` |
| `human` | per simulator | `hunav` (Gazebo) \| `isaac` (Isaac Sim) \| `dummy` |
| `robot` | `jackal` | any directory in `simulation-setup/entities/robots` |
| `seed` | `-1` | task generator seed |

Any other Arena argument (`local_planner:=`, `tm_robots:=`, `env_n:=`, ...) is
passed through to `arena_bringup/arena.launch.py`.

Examples:

```bash
arena_sim world:=house17 peds:=10                              # data-collection speed (~real time)
arena_sim world:=hospital peds:=8 render:=ogre2 gui:=true      # PBR renderer in the window (window with ogre2 not tested)
arena_sim world:=factory peds:=5-10 ped_model:=actor1,actor2
arena_sim sim:=isaac world:=map_empty peds:=6 gui:=true        # Isaac Sim RTX window
arena_sim sim:=isaac world:=isaac_hospital peds:=8 gui:=true   # Isaac hospital scene, chase camera
arena_sim sim:=isaac world:=house17 peds:=6 isaac_renderer:=PathTracing gui:=true   # not tested
```

### Verified: Gazebo, all worlds, headless, 8 pedestrians, `render:=ogre2`

Measured with `tools/test_worlds.sh 90 sim:=gazebo peds:=8 render:=ogre2`:

| World | Real-time factor | LiDAR (wall) | Pedestrians | Notes |
|---|---|---|---|---|
| `map_empty` | 0.98 | 9.6 Hz | 8 walking | |
| `house17` | 0.96 | 9.6 Hz | 8 walking | |
| `factory` | 0.35 | 3.5 Hz | 8 walking | some OGRE 1 textures not found by ogre2 (cosmetic) |
| `hospital` | 0.21–0.25 | 2–2.4 Hz | 8 walking | big world: 0.44 even without pedestrians |
| `ignc` | 0.04 | 0.4 Hz | 8, barely moving | very heavy world mesh |
| `generated` | 0.96 | 9.6 Hz | 8, **not moving** | upstream: its scenario references models that do not exist (`CoffeTable`, `KidsBed`) |

LiDAR rates are per wall-clock second; per simulated second they are ~10 Hz
everywhere. The Gazebo window was checked by screenshot (factory world, GPU
rendering through VirtualGL, `render:=ogre`); a window with `render:=ogre2` was not tested.

Topics (Gazebo): `/clock`, `/task_generator_node/jackal/{lidar,odom,imu/data,cmd_vel}`,
`/task_generator_node/human_states` and `/people` (pedestrian states), `/tf`,
plus episode topics (`/task_generator_node/{goal,task_reset,finished}`,
`/reset_start`, `/reset_end`, `/task_generator_node/jackal/evaluation`).

### Verified: Isaac Sim

* Isaac Sim 4.2 starts in the container headless and with a window (VirtualGL),
  sees both GPUs (Vulkan), loads the ROS 2 bridge and NVIDIA's people
  animation extension; first start ~100 s (shader caches), later faster.
* Arena on Isaac (`map_empty`, 6 pedestrians): robot, LiDAR (3–5 Hz, real-time
  factor 0.3–0.5), Nav2 and the USD obstacles run; all 6 NVIDIA characters are
  spawned.
* The characters walk with their animation (checked with screenshots of the
  Isaac window on a virtual display, and with `tools/isaac_ped_check.py`). Each
  walks back and forth between its spawn point and the goal Arena gives it
  (`ARENA_ISAAC_PED_LOOP=0`: stop at the goal like upstream). If Isaac's
  navigation mesh is not available they walk in a straight line, through
  obstacles. On start the viewport looks at the first pedestrian.
* With `gui:=true` the RViz window opens on top of the Isaac window. RViz shows
  no pedestrians in Isaac (their states are not published to ROS); bring the
  "Isaac Sim" window to the front to see them. The `Invalid target …/Biped_Demo…`
  and `usdSkel … Failed verification` messages in Isaac's log are harmless.
* In Isaac, robot odometry is only on TF (`odom → base_link`), not on an
  `Odometry` topic, and pedestrian states are not published to ROS.
* Obstacles in Isaac are limited to the 8 Arena models that ship a USD file
  (`BarCabinet chair_array office_chair office_long_table office_short_table
  restaurant_bench1 restaurant_table_lamp restaurant_tableset`); the others
  would need Arena's `sdf2usd` converter (OpenUSD + gz-usd + sdformat15),
  which is not available for Ubuntu 22.04 packages.
* Worlds in Isaac are built from each world's occupancy map (walls) — not from
  the Gazebo world files — so the hospital/factory 3D furniture is not there.
  For a full 3D scene use `world:=isaac_hospital` (next section).

### Isaac hospital scene: `world:=isaac_hospital`

```bash
arena_sim sim:=isaac world:=isaac_hospital peds:=8 gui:=true
```

NVIDIA's `Isaac/Environments/Hospital/hospital.usd` (corridors, patient
rooms, doors, beds, reception, carts — the scene of Arena's
`Video_hospital.gif`), with Arena's robot, NVIDIA's walking characters and
Nav2. Isaac Sim only (`sim:=gazebo` refuses it).

* World folder `simulation-setup/worlds/isaac_hospital/`: `isaac.yaml` (USD,
  floor height, prims to hide, light intensities) and `map/` — a 5 cm
  occupancy map **generated from the same USD** with
  `tools/isaac_make_map.py Hospital/hospital.usd <world>/map`, so Arena's map
  frame is Isaac's world frame. Only the area reachable from the main corridor
  with 0.3 m clearance is free (outside, closed rooms and pockets behind narrow
  gaps are occupied), because Arena picks robot starts, goals and pedestrian
  positions among the free cells. No `walls.yaml`: Isaac adds no extra walls.
* Isaac loads the USD before baking the people navigation mesh, so the
  characters walk along navmesh paths around walls and furniture (in the other
  Isaac worlds the bake runs on an empty stage and they walk in straight lines).
  Start/goal points are snapped onto the navmesh first.
* Ceilings/roofs are hidden (`hide:`): the scene is lit by its own dome light,
  which the ceiling blocks. The hospital's dome is dimmed to 3000 and Arena's
  extra dome light is off (`lights:`), otherwise the image is overexposed.
* `gui:=true` + `camera:=follow` (default): chase camera behind the robot, kept
  in front of walls by a raycast. RViz opens on top; Arena restarts it when it
  is closed, so bring the "Isaac Sim" window to the front. Live tuning while
  running: write `/tmp/arena_isaac_camera.yaml` in the container, e.g.
  `back: 3.5`, `height: 2.2`, `ahead: 2.0` [m], `mode: free`,
  `look: [x, y, z, target_x, target_y, target_z]` (fixed view, e.g. on the
  pedestrians: their start/goal points are in Isaac's log as `[wm] pedestrian`),
  `follow: <prim>` (robots only: a character's top prim stays at its spawn point),
  `dome: 0`, `lights: {/World/Environment/DomeLight: 3000}`, `exposure: 100`.
  `height: 14`, `back: 5` gives a bird's-eye view (the ceilings are hidden).
* Static obstacles default to 0 here (the scene has its own furniture).
* Verified (2026-11-11, `gui:=true`, 10 pedestrians, Xvfb screenshots + ROS
  checks): hospital rendered as in Arena's video; all 10 characters got navmesh
  paths (2–57 waypoints) and walk with their animation; the Jackal follows
  `cmd_vel` within ~0.03 m/s / rad/s and Nav2 reached 3 random goals across the
  building in 10 minutes (`tools/nav_goals.py`), at 0.45–0.56× real time with
  `isaac_hz:=20`. Some random goals still fail (narrow passages, the planner
  timing out); Arena's `explore` task then waits for its timeout and picks a
  new one.
* Pedestrian states are still not published to ROS in Isaac (RViz shows none).

## Daily use

```bash
./run.sh shell                          # interactive shell, cwd = arena4_ws, environment loaded
```

Inside the container:

```bash
arena_build                              # = colcon build in arena4_ws (+ re-source install/)
arena_build --packages-select task_generator
arena_sim ...                            # see above
arena_launch sim:=gazebo headless:=2     # Arena's own launch file, unchanged interface
arena_stop                               # kill leftover Gazebo / Isaac / Arena / Nav2 processes
```

Python packages and launch/world files are symlink-installed, so edits on the
host take effect at the next launch; C++ changes or new files need
`arena_build`.

From the host without an interactive shell: `./run.sh ws-build [colcon args]`,
`./run.sh exec <command>` (e.g. `./run.sh exec arena_stop`).

Plain `colcon build` also works inside the container: `COLCON_DEFAULTS_FILE`
points to `docker/colcon-defaults.yaml`. Parallelism is limited by default
(`ARENA_BUILD_WORKERS=8`, `MAKEFLAGS=-j4`) because the machine is shared.

`tools/arena_patches.sh status|apply|save`. Each patch is marked
`wm_social_robot patch` in the code.

| arena-isaac | `SpawnCharacters.py`: start walking to the goal given at spawn; aim the viewport at the first pedestrian | with `human:=isaac` Arena never sends a move command, so all pedestrians stood still (and were out of view) |
| arena-isaac | `MoveCharacters.py`: straight-line path when there is no navmesh | the startup navmesh bake fails in Isaac 4.2 and the move was silently dropped |
| arena-isaac | `person.py`: walk back and forth along the path (`ARENA_ISAAC_PED_LOOP`) | pedestrians stopped for good after one goal |
| arena-isaac | `run_isaacsim.py`: optional environment USD (`ARENA_ISAAC_ENV_USD`, floor offset, hidden prims, light intensities) loaded before the navmesh bake | Isaac hospital scene (`isaac_hospital`) |
| arena-isaac | `run_isaacsim.py`: follow camera (`ARENA_ISAAC_CAMERA`), live tuning file | the default view showed nothing of the robot |
| arena-isaac | `run_isaacsim.py`: render rate `ARENA_ISAAC_RENDER_HZ` (physics stays 60 Hz) | rendering every physics step ran at 0.25× real time; 20 Hz gives ~0.5× |
| arena-isaac | `MoveCharacters.py`: snap start/goal onto the navmesh, log each path | path queries failed for points just off the navmesh → straight lines through walls |
| arena-isaac | `graphs/control`: diff-drive min/max speed swap fixed; **kinematic planar drive** (`kinematic.py`, default; `ARENA_ISAAC_DRIVE=wheels` = wheel physics, then separation ×`ARENA_ISAAC_SKID_FACTOR`=1.85) | the controller got negative maximum speeds, and the skid-steer Jackal hardly turns through PhysX wheel friction (0.25 m/s + 0.5 rad/s → 0.04 rad/s), so Nav2 oscillated and failed to make progress. ## Graphics

* The ThinLinc X server has no NVIDIA OpenGL: windows go through VirtualGL
  (`vglrun -d egl`, done by `arena_sim gui:=true`). Gazebo window verified by
  screenshot (OGRE 1); Isaac Sim opens its window (verified that it starts and the ROS 2
  bridge loads; contents not inspected).
* Headless: `render:=ogre2` renders Gazebo sensors on the GPU through EGL
  (no display needed). `render:=ogre` (Arena default) needs an X display for
  its sensors. Headless Isaac runs without `DISPLAY` (`arena_sim` unsets it).
* Isaac Sim needed, and got, these host-specific fixes: NVIDIA OptiX (RTX
  denoiser) and NGX (DLSS) libraries matching the host driver are fetched by
  `run.sh build` from the host's Debian repository (`apt-get download`, no
  sudo) into `docker/nvidia-extra/`; under VirtualGL the ROS 2 bridge library
  directory is added to `LD_LIBRARY_PATH` (`arena_isaac_env`).

## Networking

The container uses its own Docker bridge network: all nodes (including Isaac
Sim's ROS 2 bridge) run inside it and discover each other normally (FastDDS,
`ROS_DOMAIN_ID=1` as in Arena's `source.bash`, 16 GB `/dev/shm`). Nothing
leaks to, or is reachable from, other users' ROS 2 or Gazebo on this shared
machine.
Fast DDS uses UDP only (`docker/fastdds_udp.xml`, loaded by `arena_env.bash`
unless `~/.ros/fastdds.xml` exists): with the default shared-memory transport,
port locks left in `/dev/shm` by killed simulator processes lost messages and
Nav2's bring-up hung at a random node (Humble's lifecycle manager waits forever
for a reply). To talk to ROS nodes outside the container you would have to add
`network_mode: host` to `docker/compose.yaml` and pick a unique `ROS_DOMAIN_ID`.

## Deviations from Arena's upstream installer (and why)

* ROS 2 Humble from apt (`ros:humble`) instead of compiling ROS 2 from source;
  Arena's Python deps installed with pip instead of pyenv + Poetry. Same
  Python 3.10, same Gazebo (Harmonic), same Isaac Sim (4.2), same pinned repos.
* Isaac Sim 4.2 is copied from NVIDIA's official image `nvcr.io/nvidia/isaac-sim:4.2.0`
  instead of pip/zip downloads: the campus firewall intercepts TLS to NVIDIA's
  download hosts (`pypi.nvidia.com`, `download.isaacsim.omniverse.nvidia.com`)
  with a certificate this machine does not trust; nvcr.io is not intercepted.
  Isaac Sim is under the NVIDIA Omniverse EULA (accepted via `OMNI_KIT_ACCEPT_EULA`
  in `compose.yaml`).
* `arena-isaac` is used at Arena's pinned commit `a4beefe0` (Isaac Sim 4.2 API);
  the repository's current default branch targets Isaac Sim 6 / Jazzy.
* Packages that cannot build on ROS 2 Humble + Harmonic are skipped explicitly
  (`docker/colcon-defaults.yaml`, `docker/Dockerfile.dockerignore`) instead of
  letting them fail with `--continue-on-error`: ROS 1 packages from
  `wg-perception/people` and `boxer`/`husky` descriptions, the Gazebo Classic
  and Fortress simulator packages of iRobot Create 3 and TurtleBot 4 (Arena
  only uses their descriptions/navigation configs), and `nav2_system_tests`.
* Gazebo rosdep rules from `osrf/osrf-rosdep` (`gz/00-gazebo.list`) so rosdep
  can resolve Harmonic's `gz-*` libraries on Humble.

## Not installed / known issues

* **Not installed:** Arena's optional planners (`.repos/planners.repos`), the
  training toolchain (torch, stable-baselines3, wandb, ...), and
  OpenUSD / `gz-usd` / `sdf2usd` (see Isaac obstacles above).
* Isaac Sim: pedestrians walk only between two points (start and Arena's goal),
  in a straight line when the navigation mesh is missing (see above).
* `generated` world: upstream scenario references missing models; pedestrians
  do not move. `ignc` runs at 0.04× real time.
* At start-up Nav2 may fail its first goal ("robot is out of bounds of the
  costmap") before the `map → jackal/odom` transform exists; the task generator
  resets and continues. Once a robot spawn timed out in `map_empty`; a rerun worked.
* Python nodes print `KeyboardInterrupt` tracebacks on Ctrl-C; harmless.
* Isaac Sim logs `carb.launcher` "failed to fork" errors for its telemetry
  helper; harmless.
* Sources are ~12 GB on the NFS home (simulation-setup assets are ~11 GB).

## Dataset tooling

`wm_dataset` does not depend on ROS or on a simulator:

```bash
python tools/inspect_dataset.py data/sample_run
PYTHONPATH=wm_dataset python examples/make_training_samples.py data/sample_run
```

The recorder that wrote this format is
`legacy_conda/ros2_ws/src/wm_social_nav/wm_social_nav/dataset_recorder.py`. It
has not been ported to Arena's topics yet (see the topic list above).
